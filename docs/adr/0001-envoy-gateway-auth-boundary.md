# ADR 0001: Centralize Edge Authentication with Envoy Gateway

- Status: Implemented
- Date: 2026-10-14

## Context

The platform previously sent public API traffic through ingress-nginx and then a custom NGINX gateway. JWT validation was implemented independently in multiple backend services. This duplicated security code across Go and Java applications and made route policy difficult to review as a whole.

Backend services remain `ClusterIP` services and NetworkPolicies restrict their application ports to the Envoy data plane. The one intentional exception is the LLM service calling public GET endpoints on the base service directly.

## Decision

Use Envoy Gateway v1.9.2 and Kubernetes Gateway API for north-south routing, TLS termination, CORS, JWT validation, and coarse rate limiting.

Keycloak remains the identity provider. Envoy validates JWT signature, issuer, audience, and expiry and maps validated claims to trusted request headers. Business services retain domain authorization such as resource ownership checks.

Protected service-to-service calls must use an explicit workload identity before they are introduced. Current service-to-service traffic does not carry end-user authority.

## Security invariants

1. Public clients cannot reach backend API services directly.
2. Untrusted identity headers are removed or overwritten by Envoy.
3. Protected routes require a valid token with the expected Keycloak issuer and backend audience.
4. Authorization involving domain data stays in the service that owns that data.
5. Services reject requests without a trusted gateway subject where authentication is required.

## Consequences

- Authentication and traffic policy become visible as declarative infrastructure.
- Backend applications carry less identity-provider-specific code.
- The gateway and its network boundary become security-critical infrastructure.
- Service-to-service calls use internal service DNS when no delegated user identity is required.
- Local Compose uses a static Envoy configuration, while production uses Gateway API resources generated by Envoy Gateway.
